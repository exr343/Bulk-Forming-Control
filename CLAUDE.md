## What this is

This repo is **Agility Forge**: a differentiable thermo-mechanical simulation of multi-hit rotational forging, built for a CIRP 2027 submission, plus a MeshGraphNets-style GNN surrogate and an MPC control loop around it (both implemented and validated — see stages 2/3 below). See [README.md](README.md) for the pipeline overview. An earlier Koopman Autoencoder surrogate was explored first and is still present in the repo (`applications/Agility_Forge/koopman/`), but the GNN surrogate is now the active stage-2 approach.

It started as a clone of [JAX-FEM](https://github.com/deepmodeling/jax-fem) plus its full example-application gallery, docs, and test suite; those were stripped out (they weren't dependencies of this project) leaving only the forging-specific code. `jax_forge/` — the FEM core Agility_Forge actually runs on — is a project-specific fork of JAX-FEM (originally named `jax_fem_checkpoint/`, renamed once the unmodified upstream copy it was disambiguated against was removed). If you're looking for the general-purpose JAX-FEM library/example gallery, it isn't here; this repo is scoped to forging + the surrogate/control pipeline only.

## Common commands

Run everything as a module from the repo root (not as a script from inside subdirectories), since imports are absolute (`jax_forge...`, `applications...`).

```bash
# Agility Forge: single multi-hit forging run (fixed hit schedule)
python -m applications.Agility_Forge.main

# Agility Forge: randomized hit schedule
python -m applications.Agility_Forge.main_random_hits

# Agility Forge: dataset generation (many rollouts, for training data).
# Appends to an existing dataset dir rather than replacing it -- rerunning
# adds more rollouts instead of discarding what's there. Omit --seed for a
# fresh (non-reproducible) draw each run; pass one for a reproducible run.
python -m applications.Agility_Forge.generate_dataset --n-rollouts 25 --n-hits 5

# GNN surrogate training (stage 2 — implemented and trained at full reference
# sizing against the full 3D actuation space; see GNN/README.md for the
# message-passing depth sweep and current results)
python -m applications.Agility_Forge.GNN.train --dataset-dir applications/Agility_Forge/data/dataset_pretraining --epochs 100

# Scheduled square-rod rollout for GNN finetuning (see generate_square_rollout.py)
python -m applications.Agility_Forge.generate_square_rollout --dataset-dir applications/Agility_Forge/data/dataset_finetuning/square

# Finetune the 5-step GNN checkpoint on the square-rod runs (+ pretraining replay)
python -m applications.Agility_Forge.GNN.finetune

# Koopman Autoencoder training (earlier stage-2 approach, superseded by the GNN surrogate above;
# code still present/runnable for reference)
python -m applications.Agility_Forge.koopman.train --dataset-dir applications/Agility_Forge/data/dataset_pretraining --epochs 100
```

There is no lint/format config in this repo and no test suite yet (the upstream benchmark tests that shipped with JAX-FEM tested the now-removed unmodified library, not `jax_forge` or Agility_Forge — there's no existing test coverage for this project's own code).

## Architecture

### FEM core (`jax_forge/`)

- `generate_mesh.py` — `Mesh` container and mesh-generation helpers (`rectangle_mesh`, meshio interop, `get_meshio_cell_type`).
- `basis.py` / `basis_new.py` — reference-element shape functions/gradients per element type and quadrature.
- `fe.py` / `fe_new.py` — `FiniteElement`: one FE variable (mesh + vec + dim + ele_type + Dirichlet BC info); assembles per-variable shape data.
- `problem.py` / `problem_new.py` — `Problem`: composes one or more `FiniteElement`s (`self.fes`) into a (possibly coupled multi-physics) weak form. Problems subclass `Problem` and override `get_tensor_map` / `get_mass_map` / `custom_init` / a `universal_kernel` for the weak form, plus `set_params`/`set_timestep` for time-dependent/parametric runs.
- `solver.py` / `solver_latest.py` — Newton/nonlinear solve driver (`solver(problem, ...)`); `solver_latest.py` is the one Agility_Forge's time stepper actually calls. Supports JAX, scipy, and PETSc (`petsc4py`) linear solves, with optional AMGX (`pyamgx`, optional dependency) and adjoint/differentiable solves.
- `mma.py` — Method of Moving Asymptotes (topology-optimization-style problems; not currently used by Agility_Forge).
- `experimental/` — newer/unstable features (custom JVPs, adjoint checkpoint-to-disk, sparse utilities, JIT strategy helpers), not part of a stable API.

The `_new`/`_latest` files (`fe_new.py`, `problem_new.py`, `basis_new.py`, `solver_latest.py`) are further-diverged variants layered on top of the base files during this project's development — check which one a given Agility_Forge module actually imports (`grep` for `jax_forge\.` in `applications/Agility_Forge/`) before assuming `fe.py`/`problem.py`/`solver.py` are the live code path.

### `applications/Agility_Forge/` — stage 1: forging simulation & data generation

- `hit_config.py` — `Hit` dataclass: parameters for one forging hit (die position, compression displacement, rotation, duration). The die position is either `die_center_mm` (spatial die: 12.7 mm wide `DIE_WIDTH_MM`, the JAX-FORGE paper's flat tool, fixed in space and pressing the points currently under it; added 2026-10-02) or `x_min_band`/`x_max_band` (the original 19.3 mm band as fractions of H on the undeformed bar, which every dataset before 2026-10-02 used and every data-gen/MPC script still uses). Keyword-only; exactly one of the two must be given.
- `lib/constitutive.py` — `ThermalMechanical(Problem)`: coupled thermo-mechanical `jax_forge` problem — temperature-dependent J2 finite-strain plasticity with F-bar, plus the coupled weak form and stress/internal-variable post-processing. Material parameters come from `material_data.py`.
- `lib/boundary_conditions.py` — `build_cylinder_press_bcs(...)`: constructs Dirichlet BCs for the rotating cylindrical press/platen contact (updated-Lagrangian, re-detected from the current deformed surface each step; which nodes are under the die is decided from current x for the spatial die, every step, and from reference x for the original band) plus convective BCs; `refresh_problem_surface_integrals(...)` re-applies them to a `Problem` after BCs change mid-run.
- `lib/time_stepper.py` — `AutomaticTimeStepperTM`: adaptive-dt Newton time-stepping loop around `jax_forge.solver_latest.solver`, with retry-on-failure, extrapolated initial guesses, VTK output, and step-history plotting. `seed_state(...)` primes/resets the extrapolation history — must be called whenever the solution is externally reset (e.g., between hits) to avoid a doubled first-step initial guess.
- `mesh_container.py` — `MeshContainer`: loads/converts stock geometry (Open3D mesh → JSON → jax-fem `Mesh`).
- `main.py` — driver for a fixed multi-hit rotational forging schedule; handles inter-hit thermal-state relaxation (ramped `T_old` blend + re-equilibration, since resetting temperature in one shot produces a dt-independent Newton stall) and rebuilds contact BCs on the post-relaxation surface each hit.
- `main_random_hits.py` — same driver logic with randomized hit schedules.
- `generate_dataset.py` — runs many randomized rollouts (`run_dataset_generation`, CLI via `--n-rollouts/--n-hits/--seed`) and writes a manifest (`ManifestWriter`) plus one `.vtu` per saved state (per-node `Displacement` + `Temperature`) — this is the training data source for stage 2. This is what `submit_dataset_generation.sh` invokes on the cluster. **Appends** to an existing dataset dir across invocations rather than wiping it: rollout numbering continues from the highest existing `rollout_XX`, `manifest.json` merges (records accumulate, `generation_runs` tracks one provenance entry — seed/n_rollouts/timestamp — per invocation), and a run whose `--n-hits`/`--band-width-frac`/`--min-compression-displacement`/`--max-compression-displacement`/`--total-time` doesn't match the dataset's existing config is rejected rather than silently mixed in. `--seed` defaults to fresh OS entropy (not a fixed value) so repeated runs add *new* rollouts. As of the 3D-actuation-space expansion, `u_j` (strike depth) is a third independently-randomized per-hit parameter (`Uniform(--min-compression-displacement, --max-compression-displacement)`, default 0.5-2.0mm — see the module docstring for why), alongside the existing `d_j`/`R_j`; the earlier 2D-actuation dataset (`d_j`/`R_j` randomized, `u_j` fixed at 2.5mm) has been preserved at `data/backup/dataset_2dim` rather than overwritten.
- `generate_square_rollout.py` — scheduled (not random) rollouts for GNN finetuning, reusing `control/plant_interface.ForgingPlant.step`. Default: a 48-hit square-rod schedule (6 stations × 0°/90° × 4 passes of shrinking target thickness, adapted from a collaborator's industrial toolpath scaled to this billet). The stroke is computed per hit from the current surface (half-thickness − target half-gap), capped at 2mm (`capped` flag in the manifest). `--jitter-seed N` perturbs station positions (±3.7mm), angles (±5°) and pass thicknesses (±0.2mm); `--part bulge_head` is a thin/bulge/thin/head variant. Stations stay above the 800°C point of the initial temperature profile (x≈17.7mm). Checkpoints the full solver state after every hit (resumes on rerun), retries a failed hit once as two half-strokes, logs failed attempts to `failed_hits.jsonl`, and builds the mesh under a file lock (parallel jobs raced on the shared `msh/.../tmp` scratch files otherwise). One single-rollout dataset dir per run, in `generate_dataset.py`'s manifest format.
- `generate_square_coil_rollout.py` — the rollouts on the NEW simulator (12.7 mm spatial die + coil reheat every 6 hits, README "The reheat"; a reheat keeps the hotter of current and coil temperature, `reheat_temperature` in `control/plant_interface.py`): simple_square scaled to this billet, two passes (half-gap 6.27 then 5.3 mm) plus `--extra-passes 2` at 5.3 mm, 0/90 deg per station, 10.73 mm station step from 31.58 mm to the free end, no taper hit; cycle = scan -> plan 3 stations -> `ForgingPlant.reheat` with `coil_temperature` centred on their midpoint -> hits with `step(..., reheat=False)`. `--jitter-seed N`: station +-1.0 mm, angle +-5 deg, half-gap +-0.2 mm. Writes `data/dataset_die12_coil/{square,square_jitter_seedN}`; reheats/skips are stored in the manifest outside `records`. Same checkpoint/resume and half-stroke retry as `generate_square_rollout.py`; a failed reheat retries at 25 then 12.5 C/step. `--linear-solver scipy` uses a direct sparse solve instead of the default unpreconditioned BiCGSTAB: late in a run (first reheat of pass 4) BiCGSTAB stops converging and the reheat NaNs even with no temperature change, while the direct solve passes (`output/reheat_failure_diag/`); 8 of the 10 runs of job 3955595 stopped there and were resumed with it (`slurm_scripts/submit_square_coil_resume_direct.sh`). After 4 passes no run reached the target (mean widths 11.8 / 11.2 mm at 0/90 deg vs 10.6; the stroke cap wasn't the limit, each 90 deg hit pushes the 0 deg sides back out), so a 5th pass continues each run into `data/dataset_die12_coil_5pass/<run>` (`--continue-from ... --extra-passes 3 --last-pass-half-gap G`, `slurm_scripts/submit_square_coil_pass5.sh`) with G spread evenly 5.0-5.3 mm across the 10 runs (plain square 5.0 ... seed 9 5.3), so the data spans just above to slightly past the target. Two passes alone (34 hits) ended ~13 mm thick and 122 mm long vs the target's 10.6 mm / 153 mm (about half of each squeeze spreads sideways with this die, and every 90 deg hit hit the 2 mm cap), hence 4 passes. Earlier runs used `--overwrite-reheat` (every node set to the coil profile), which cooled far zones ~300 C and failed at pass starts; they, and the `--continue-from`/`--reverse-passes`/`--reverse-failed-pass` workarounds (`slurm_scripts/submit_square_coil_extend*.sh`), are historical, data in `data/backup/die12_coil_overwrite_reheat/`.
- `data/` — four folders: `msh/` (mesh assets, a real input — hardcoded path, don't move); `dataset_pretraining/` (stage 1's random-hit output from `generate_dataset.py`, what the GNN was trained on); `dataset_finetuning/` (scheduled rollouts from `generate_square_rollout.py`: `square/`, `square_jitter_seed{1,2,3}/`, `bulge_head/`); `backup/` (old diagnostics/VTK output plus the superseded `dataset_2dim/`). Git-ignored. Don't write into a dataset folder while a job is actively running against it (manifest.json is rewritten after every saved record).

`open3d` is an optional import in `main.py`/`main_random_hits.py`/`generate_dataset.py` — mesh-conversion functions are disabled with a warning if it's not installed.

### `applications/Agility_Forge/GNN/` — stage 2: MeshGraphNets surrogate (implemented, trained at full reference sizing against the 3D actuation space)

`GNN/old/` holds a wholesale, unmodified sparse-checkout of [google-deepmind/deepmind-research's meshgraphnets](https://github.com/google-deepmind/deepmind-research/tree/master/meshgraphnets) (`core_model.py`, `common.py`, `normalization.py`, `cfd_model.py`/`cloth_model.py`, `dataset.py`, `run_model.py` — TF1/Sonnet/graph_nets, kept for reference only, not runnable against this project's data; moved into `old/` — also gitignored there — since it isn't part of the hot-forging project itself) alongside the actual Agility_Forge-specific PyTorch port, which lives directly in `GNN/`: `normalizer.py` (`OnlineNormalizer`, ported from `normalization.py`), `data.py` (surface-mesh extraction, per-hit example loading, `ForgeGNNDataset`, `u_j_frac` control-broadcast dim), `model.py` (`MLP`/`GraphNetBlock`/`EncodeProcessDecode`/`ForgeGNN`, ported from `core_model.py`), and `train.py` (training loop + an autoregressive rollout eval that dumps true/predicted `.vtu` pairs, a per-hit MSE/NRMSE curve, and Chamfer/Hausdorff). Filenames for the port deliberately avoid colliding with the vendored `normalization.py`/`dataset.py`. Full rationale for every settled design decision (step granularity, graph structure, actuation/contact encoding, output parameterization, state fields, training regime, normalization scheme) plus a message-passing-depth sweep (`mp_sweep/`, 1/5/15/45/135 steps — accuracy saturates at ~5, no benefit from going deeper) is in `GNN/README.md`. This is the active stage-2 approach, superseding the Koopman Autoencoder below, and is now wired into the MPC control loop (stage 3) below. `finetune.py` finetunes `mp_sweep/checkpoint_mp_5.pt` on `data/dataset_finetuning/` square runs (test run `square_jitter_seed3`), reusing `train.py`'s loss/metrics/early stopping. Normalizers are frozen, lr 1e-5, and `--replay-ratio` mixes in freshly sampled pretraining-train hits each epoch to prevent forgetting. It writes `GNN/finetune_square/`, which the SLURM script wipes at the start of every run, so results are recorded in `GNN/README.md`. The MPC scripts still default to the un-finetuned checkpoints.

`coil.py` is the separate three-stage pipeline for the NEW simulator (16 inputs incl. die push, coil temperature and a reheat flag; old random → old square → new 5-pass runs (`data/dataset_die12_coil_5pass`) with cycle-chain training; M = 1–10 sweep into `GNN/coil_sweep/`; stage-3 results from the first, partial 4-pass data are in `coil_sweep/partial_4pass_2026-10-05/`). Split: test seed 3, validation seed 9 (early stopping), the rest train; `--test-run square` holds out the plain square run instead (stages 2 and 3; stage 1 reused via `--stage1-from`), written to `GNN/coil_sweep_test_square/`. Figures (loss curves, rollouts, comparison GIFs): `output/gnn_figures/heldout_seed3/` (frozen-temperature GNN, seed 3 held out) and `output/gnn_figures/tstate_heldout_square/` (coil_T.py, plain square held out; `rollout.py --tstate` also rolls temperature out and plots its error), scripts in `output/gnn_figures/`. `coil_T.py` (2026-10-07) is the same pipeline with temperature in the nodal state: the GNN predicts the change of displacement AND temperature per hit (4 outputs), the temperature input is the real surface temperature (an IR camera in practice; replaces coil.py's bookkept coil temperature, which saturated at ~1096 C and missed the die chill), a reheat's temperature is the simulator's exact rule (hotter of current and coil profile); sweep `GNN/coil_T_sweep_test_square/` (plain square held out), scripts `slurm_scripts/submit_gnn_coilT_*.sh`. coil.py is kept unchanged as the frozen-temperature baseline. `finetune_mpc.py` (2026-10-08) finetunes `coil_T_sweep_test_square/mp_5/stage3.pt` on the MPC runs' own hits (DAgger-style; every 4th complete MPC cycle held out, plus replay of the 5-pass training cycles and stage 3's old-random mix-in; early stopping on held-out MPC cycles + seed 9), writes `GNN/coil_T_mpc_finetune/mp_5/`, script `slurm_scripts/submit_gnn_coilT_finetune_mpc.sh`. See `GNN/README.md`, "Coil / spatial-die GNN".

### `applications/Agility_Forge/koopman/` — earlier stage-2 approach: Koopman Autoencoder (implemented, proof-of-concept; superseded by `GNN/` above)

Modeled on `peter-frazier/KAE_for_uniaxial_tensile_test`'s `LRAN_BLRAN/LRAN_LD`, with one deliberate departure: the original state does **not** appear in the latent (`z = Psi(x)`, not LRAN_LD's `z = [x; Psi(x)]`). Full rationale for every design decision (state representation, control encoding, normalization, loss terms, architecture sizing) is in `koopman/README.md`'s "Design decisions (implemented)" section. Code is left in place and still runs, but new surrogate-modeling work should go into `GNN/` instead of here.

- `dataset.py` — loads `manifest.json` + `.vtu` rollouts. State is the flattened `Displacement` field per node (`n_x = n_nodes*3`, no reduction) — Temperature is present in every `.vtu` (jax_forge's coupling is unchanged) but is not read into the state; control is `[d_j_frac, sin(R_j), cos(R_j)]` used **raw** (Koopman convention: only the state is normalized/lifted, not the input); state normalization is pooled per physical quantity (one `[-1,1]` scale across all `Displacement` components) so per-axis rescaling doesn't distort displacement direction, fit on the training split only. `compute_pod_basis` additionally fits a fixed (non-learned) rank-`r` POD basis (mean-center + economy SVD of the normalized training states) that `build_rollout_dataset(..., n_pod_modes=r)` returns via `info["pod_mean"]`/`info["pod_modes"]` for the model to consume — see `applications/Agility_Forge/SVD/` for the analysis that motivated this. One training window per rollout (`K = n_hits_per_rollout`), prefix train/test split by rollout index.
- `model.py` — `KoopmanAutoencoder`: pipeline is state -> POD (fixed) -> lift (learned) -> linear dynamics -> unlift (learned) -> POD^-1 (fixed). `encode`: POD-project the `n_x`-dim normalized state onto the fixed `r`-dim basis (`pod_mean`/`pod_modes`, registered buffers — not learned), then `Lifting` (`z = Psi(a)`, `n_z > r` deliberately — Koopman theory lifts to a *higher*-dim space) lifts the `r`-dim POD coefficients to the `n_z`-dim latent. `Lifting` is `in_proj(r->block_widths[0])` -> one residual block per entry in `block_widths` -> `out_proj(block_widths[-1]->n_z)`; each block wraps `layers_per_block` `[LayerNorm -> Linear(width,width) -> activation]` layers in one skip connection (`out = in + F(in)`), with a plain Linear+activation transition (no skip) bridging blocks whose widths differ — skipped (no extra layer at all) when consecutive widths match. `decode`: learned linear `n_z -> r` (`nn.Linear`, not exact), then the *fixed* POD reconstruction `pod_mean + a_hat @ pod_modes` back to `n_x`. `A`/`B` linear dynamics (`z_{k+1} = A z_k + B u_k`) operate on the `n_z`-dim latent, unchanged in kind. Default `r=75, n_z=250, block_widths=[250,250,250,250], layers_per_block=8` (32 hidden layers, ~2.19M learned params) — replaced an earlier `n_x`-input, ~2.4B-param design once `applications/Agility_Forge/SVD/`'s POD energy analysis showed that scale wasn't justified by the data (~11/30/71 modes for 90/95/99.9% energy on the full 25-rollout dataset). LayerNorm (needed for stability in the earlier wider/deeper version) is kept and still empirically stable at this smaller scale.
- `train.py` — `L_id + L_fwd + L_lin` (+ optional `L_eig`, off by default) loss, early stopping on test `L_fwd`, per-epoch train-vs-test loss-curve plot + `metrics.json`, true-vs-predicted `.vtu` dump for one held-out rollout. Default architecture as above (`--n-pod-modes 75 --latent-dim 250 --block-widths 250,250,250,250 --layers-per-block 8`) — sized to what the SVD/POD analysis actually justified, not (unlike the prior default) a bet sized for a much larger future dataset; still expect some overfitting risk at 20-25 training rollouts even at this much smaller scale. Deliberately imports its own stdlib logger rather than `from jax_forge import logger` — `jax_forge/__init__.py` has import-time side effects (prints a `pyfiglet` banner, pulls in the JAX/FEM stack) that this module is meant to stay decoupled from.
- `applications/Agility_Forge/SVD/` — **removed** (was a standalone POD/SVD analysis that motivated the `koopman/` module's fixed POD pre-reduction; deleted since it's not used by the active `GNN/` approach, which operates on the raw mesh, not a POD-reduced state). Historical rationale still described in `koopman/README.md`.

### `applications/Agility_Forge/control/` — stage 3: MPC loop (implemented and validated against the real plant)

`plant_interface.py` (`ForgingPlant`: wraps `ThermalMechanical`/`AutomaticTimeStepperTM` behind a `step(state, hit) -> next_state` interface, mirroring `generate_dataset.py`'s per-hit loop exactly including the thermal relaxation ramp) and `mpc.py` (`MPCController`: single-shooting SQP-BFGS planner via `scipy.optimize.minimize(method="SLSQP")`, using the GNN surrogate for planning gradients and the real plant for ground truth in `run()`'s receding-horizon loop) are both implemented. Validated open-loop (one planned 5-step sequence applied to the real plant: 0.15mm RMSE vs. target, matching the surrogate's own 0.152mm prediction almost exactly) and closed-loop (5 independent held-out targets, re-planning from the plant's true state before every real hit: 0.17-0.27mm RMSE each). See `control/README.md` for the full design-decision rationale and results table.

`mpc_coil.py` is the MPC for the NEW simulator, updated 2026-10-08 for the temperature-state GNN (`GNN/coil_T.py`): each scan reads shape AND the real surface temperature (IR camera in practice), the reheat rule (hotter of measured and coil profile) is applied at the start of the 6-hit forecast, predicted temperature is carried hit to hit; 6 hits planned per scan and all applied, coil at the average of the planned die centres, planner = random shooting + top-K SLSQP refinement since 2026-10-08 (RoboCraft-style: N = 100 uniform plans scored by the GNN in batches without gradients, the K = 5 best each refined by the unchanged SLSQP independently, best kept; `--n-samples 1` = old single default start; deterministic CUDA on for repeatability; checks + GNN-only comparison in `control/ablation_multistart.py`, report `progress/control_reports/2026-10-08_multistart_planner/`), the +-11 mm coil-zone constraint was removed (2026-10-08), any angle 0-180 deg, cross-section cost (unchanged, no temperature term), stop when every width from the first station (31.58 mm) is <= 10.8 mm or after 20 cycles, direct linear solver. First run (single start, coil zone): M = 5 (`GNN/coil_T_sweep_test_square/mp_5/stage3.pt`), job 3984018 -> `control/results/coil_mpc_tstate_M5/`, stopped at hit 62 (plans exploited GNN error; worse than the scheduled run). A second run (multi-start, no coil zone, job 3990381) was cancelled before it started (2026-10-08). Ensemble uncertainty penalty (2026-10-08, not yet run): `--checkpoints` (deep ensemble of coil_T models; `--checkpoint` = 1 member) and `--var-weight` lambda: each member rolls the plan from the same scan, cost = cross-section error of the members' mean shape + lambda * sum over hits and nodes of the members' y,z variance (1/M; both mm^2), in the screening and the SLSQP alike; one checkpoint with lambda = 0 reproduces the previous planner bit for bit; per-cycle `cost_terms` in the manifest. Members: seed 0 = `GNN/coil_T_sweep_test_square/mp_5/stage3.pt`, seeds 1-4 trained by `slurm_scripts/submit_gnn_coilT_ensemble.sh` into `GNN/coil_T_ensemble_test_square/seed_k/`; check the spread first with `GNN/ensemble_calibration.py` (spread vs error per hit; fallback if weak: bootstrapped members); lambda sweep {0, 0.1, 1, 10} by `slurm_scripts/submit_mpc_coil_ensemble.sh` -> `control/results/coil_mpc_tstate_M5_ens_lam<lambda>/`.
